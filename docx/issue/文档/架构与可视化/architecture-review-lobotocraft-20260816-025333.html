Problem：一个 interface 同时要求调用者理解运行时、百科、音频、工具、E.G.O 和渲染事实，默认方法还直接拼中文展示文本。

4. 明确异想体状态的重载语义

Strong in-process

EntityBigBadWolf.java · EntityBlueStar.java · EntityCensored.java · EntityNothingThere.java · EntityQueenOfHatred.java

Big Bad Wolf

保存 `InFog`，不保存 `fogTimer`。

Blue Star

行为依赖 TimerEntry，无实体 NBT。

CENSORED

多项攻击/献祭状态，无持久化入口。

Queen

显式状态机并保存主要阶段。

Reload policy

Resume Cancel Rollback

每个状态必须声明重载行为，并由同一 Seam 执行和测试。

Problem：同类状态在区块卸载、停服重进后的处理没有共同规则，甚至存在“保存布尔量但不保存配套计时器”的无效组合。

Solution：每个运行状态显式选择恢复、取消或回滚，并把序列化与恢复校验放在同一 Module。

tests：NBT round-trip 与卸载/重载成为固定 test surface；locality：状态字段和恢复不再分散。

生成/删除持久化 订单工作 近战/远程恐慌 AI 自动索敌YSM 外观 一个静态 Module 承担全部转换

Employee runtime

外部 interface 保持分配订单、查询和恢复。

内部订单状态机内部战斗决策 内部持久化内部外观 Adapter

Problem：文件大不是唯一问题；生成、死亡、订单、导航、战斗、E.G.O 和外观共享同一批静态状态，改任一流程都要理解整类。

Solution：保持外部 interface，先在 Implementation 内建立真正的内部 Seam，让订单和战斗状态机可独立测试。

locality：订单 Bug 不再穿过死亡/YSM 代码；leverage：26 个调用者无需变化。

事件订阅留在各自 Module，Forge 事件只是 Adapter。

Problem：事件类按 Forge 事件类型聚合，而不是按领域状态聚合；死亡或伤害顺序变化可能同时影响多个无关机制。

Solution：让每个领域 Module 拥有自己的 Forge Adapter，事件集散点只保留真正跨域的协调。

locality：每条生命周期的订阅、顺序和测试集中；depth：Forge 细节藏在 Adapter 后。
