# 近期问题底层排查记录

日期：2026-08-08

状态：仅完成只读排查，以下方案等待批准后执行。

最近一次构建：`build` 与 `verifyReleaseJar` 均通过。

## 1. 红舞鞋受控员工

### 原因

- `EmployeeRuntimeManager.tick` 遇到红舞鞋控制状态就停止导航和战斗。
- AI 威胁筛选只处理恐慌员工、出逃异想体和敌对生物，没有把受控员工视为敌人。
- `FacilityCombatRules` 只把“受控攻击者”作为敌对条件，没有把“受控受害者”纳入规则。
- 服务器关闭 PVP 时，玩家伤害可能在 Forge `LivingAttackEvent` 之前被原版拦截。

### 方案

建立统一的员工敌对状态判断，同时接入 AI 目标筛选、友伤规则和 PVP 入口。受控员工可被 AI 和玩家攻击，攻击来源保留正常归因；解除控制后立即恢复友方状态。

## 2. 冰雪女皇冰封与决斗

### 原因

- 冰封由永久 `isSnowQueen` 标记和亲吻效果共同判断，两个状态没有统一生命周期。
- 亲吻效果可能过期，但冰封标记仍存在，导致既不能普通工作，也不能决斗。
- 决斗目标不是固定绑定的，而是在完成时重新搜索附近任意冰封玩家。
- AI 管理器会先取消冰封员工的工作，没有区分普通工作和救援决斗。
- 没有唯一占用检查，重复工作可能再次建立冰封状态。

### 方案

建立明确的冰封记录：来源异想体、目标 UUID、状态阶段。救援决斗先通过专门授权，再阻止普通工作；完成时只解除绑定目标，并防止重复建立或错误解除其他冰封状态。

## 3. 击败终末鸟后插图消失

### 原因

- 终末鸟在 `setHealth(0)` 中发送死亡 CG，但该入口可能重复调用，没有一次性完成标记。
- 全屏渲染器是全局单例，新图片会覆盖旧图片；当前渲染还依赖 HOTBAR overlay。
- 终末鸟死亡、三鸟恢复、奖励发放和实体移除没有作为一个演出事务处理。

### 方案

把“三蛋完成、终末鸟死亡、奖励、CG”合并为一次服务端事务，增加演出 ID 和优先级。客户端收到终末鸟胜利演出后锁定该演出，避免被重复死亡消息或其他 CG 覆盖，并改为独立 GUI overlay。

## 4. 一无所有

### 原因

- 当前低正义判断使用 `<3`，需求是“正义低于4级”，应覆盖1至3级。
- 失败伤害发生在工作提取阶段；员工死亡后工作会话被取消，后续 `onWorkComplete` 不再执行，导致套皮回调丢失。
- `onBadWork` 先触发出逃，随后 `onWorkComplete(BAD)` 又执行击杀套皮，两个结果互相冲突。
- 失败伤害路径使用 `>4`，4级员工不会套皮；需求应为不低于4级。

### 方案

把工作结果、失败伤害、员工死亡、套皮和出逃改成明确的单次状态机：

- 正义低于4级：工作后出逃。
- 正义不低于4级：被失败伤害杀死后套皮。
- `BAD` 结果只执行直接出逃，不套皮。
- 死亡发生在提取阶段时，由工作管理器发送一次失败死亡回调，不能依赖后续完成回调。

## 5. `doImmediateRespawn=true` 与“我们可以改变一切”

### 原因

- `EntityIronMaiden` 只保存使用者 UUID，并通过 UUID 每 tick 重新获取玩家。
- 立即重生会替换玩家实体但保留 UUID，机器于是把新生命误认成旧会话并继续工作。
- 机器没有在玩家死亡事件上立即终止会话、释放牺牲目标和清理状态。
- 公共死亡逻辑每次死亡都会生成文职，持续会话会把这个问题放大成大量文职。

### 方案

工具会话绑定实体实例或生命周期代次，而不是只绑定 UUID。死亡事件立即终止机器、释放牺牲目标并取消关联工作；重生后的新实体不能继承正在运行的工具会话。

## 6. 小鸟回收容室坐标偏移

### 原因

- 黑森林捕获记录优先保存 `getEscapePosition()`。
- 小鸟返回时会把该字段设置为 `nestPosition.above()`，它和收容室 marker 不是同一种坐标语义。
- 公共回收逻辑优先使用逃跑位置，恢复逻辑又会在附近扫描候选位置，混用了巢方块、实体脚底和方块中心坐标。

### 方案

统一所有实体位置为“实体脚底所在方块坐标”。小鸟使用巢方块上方作为唯一锚点；回收优先使用收容室 marker/巢位置，只有碰撞箱放不下时才进行确定性的最近位置搜索。收到截图后再确认具体偏移轴向。

## 7. 拟态回血

### 原因

- `NothingThereWeapon` 当前按请求伤害直接回血，并且没有要求 `hurt` 成功。
- 抗性、伤害取消、E.G.O 加成和其他事件修改都发生在最终伤害结算链中，因此当前回血值不是实际伤害。
- 红色抗性为0或伤害被取消时，仍可能按原始伤害回血。

### 方案

增加统一伤害事务，在最终伤害阶段读取实际造成的生命伤害，只按最终值回血：

- 实际造成2点，回血2点。
- 伤害被取消、抗性为0或最终伤害为0，不回血。
- 保留非完整拟态50%、完整拟态100%的倍率。
- 对多段攻击、吸收伤害和致死伤害分别验证，确保一次伤害只触发一次回血。
