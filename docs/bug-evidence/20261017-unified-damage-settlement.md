# 四色伤害统一结算（2026-10-17）

## 授权与范围

用户明确：“所有红白黑蓝那些伤害还有什么加算计算应该统一处理”，并要求“开始改吧，记得把源码冲突的地方也修改一下”。

本轮以改动前 `06f79a0` 为源码基线。既有未提交的教堂台账/CONTEXT/证据修改保留，不混成伤害修复。教堂生成与性能保持用户已接受的现状；不实施烟气BUFF及未定持续时间，不改网络注册ID、颜色注册键、存档或图鉴数据。

## 实现

- `combat.DamageSettlement` 是本模组Hurt及Damage阶段的唯一数值编排入口，继续走Minecraft/Forge的 `hurt`、护甲、吸收、死亡及责任归属，不用全局减血管理器接管生命。
- 颜色/抗性/生命与精神分流的计算集中在 `DamageCalculation`。内部使用PALE，旧registry/network `blue`仍兼容，未批量改名破坏存档。
- 装备自身条件/几率继续在原有模块内维护，但贡献方法移除独立事件订阅，由统一入口显式调用一次；不是新增入口同时保留原监听器。
- 现有独立加算/乘算顺序保留为明确序列，不把全部套装百分比重新分组相加。冰片倍率＋最大生命附伤、饰品固定＋1/＋2/＋15、独立百分比等按原函数内部顺序执行。跨监听器原依赖注册顺序的部分现固定，不能声称所有旧隐式组合数值完全不变。
- 目标抗性只读取实际Attribute和已有Geburah专用覆盖，不读取展示后备表。DOT共享此来源，蜂后“仅正抗可忽略”规则保留，零抗/负抗不被改成1。

### 明确阶段

1. 原版攻击合法性、友伤、远程阻挡和Forge前置取消继续执行。
2. 外部Hurt的LOW及更早优先级修饰/取消完成后，统一入口执行本模组显式输出贡献：蓄力、尸山输出、既有装备输出、溢血、羊皮输出、亡蝶、Geburah镇压奖励；随后受击装备、蜂后承伤及羊皮单次受击记录。输出与承伤不再混成依赖注册顺序的先后关系。
3. 尸山WHITE盾拦截；读取统一抗性、核心抑制倍率、斯卡蒂四色祝福及本次满精神上限快照。
4. 一次计算分成HP/SP损失或恢复。HP候选先走既有一无所有/碧蓝免死与开路甲回调，之后应用SP；HP继续交回原版减伤及扣血。
5. 原版减伤后的Damage阶段：DOT精确量恢复→现有生命保护/最终上限→斯卡蒂免死→伤害收益→红姐姿态/生命适配。伤害历史最后收尾，取消或纯SP路径亦清理。

注意：`DamageCalculation.Result.healthDamage` 是交给原版的**扣血候选量**，不是已经观察到的最终生命损失。最终生命收益仍在Damage阶段读取既有最终健康伤害近似，不用该中间结果冒称实际损血。BLACK的SP与原版HP护甲减伤仍按既有双通道语义分别处理；Damage阶段的生命专用保护不自动等同攻击整体取消。

### 源码冲突处理

- 删去 `MentalValueEventHandler` 的整段四色/负抗/边框监听与私有抗性分支，只保留精神状态本身的管理。
- 删去 `ForgeModEvent` 的重复四色抗性与负抗恢复分支，常规装备变成显式贡献。
- 删去Attack/Hurt中额外白伤安抚/黑伤重复恢复和用虚空伤害递归补HP的路径。WHITE恢复按已确认的“目标恐慌、责任玩家正常”统一判定一次，BLACK照常双通道结算。
- 尸山BLACK盾不再用持久标记“先扣精神再LOWEST补回”，直接屏蔽SP通道；不会先触发恐慌、CENSORED减计数等副作用再恢复数值。
- 斯卡蒂祝福40%承伤修饰移至统一分流前，覆盖WHITE/BLACK精神；Damage回调只处理免死，不重复乘0.6。
- DOT在所有修饰后记录HP候选，在最终上限/免死之前恢复真伤值，不再按监听器注册顺序覆盖生命保护。
- 伤害历史finish不再和统一结算争抢LOWEST顺序；由统一入口finally收尾。原始捕获仍在HIGHEST，最终HP记录仍在原版扣血之前。
- 羊皮潜狼收到玩家伤害的重复累计分支移除，所有来源只保留一次受击累计，避免原来同次伤害累积两遍。
- 非玩家红抗0仍以普通Hurt链路的amount0实现，不改为直接拒绝；Geburah对一无所有三阶段的既有覆盖保留。

### 不属于本轮的旁路

机制处决、工作固定生命/精神惩罚、资源消耗、初始化、复活、回收回血不机械替换为普通四色伤害。不声称已经审清每个 `setHealth` 或每个实体专属技能数值。攻击命中特效/既有尝试命中触发器的时点不等于最终扣血：本轮没有重做全部装备proc语义。

其他模组在同LOWEST且晚于本入口的Hurt监听仍可能继续改变HP候选；不承诺跨任意模组强制最后执行。若未来要支持可取消的跨模组事务，需要专门设计，不用全局伤害源Map拼一个潜在泄漏的事务。

架构只读核查发现大鸟已有 `hurt(fellOutOfWorld, +Infinity)`。最初普通非有限值保护会取消它，现明确执行来源的+Infinity先归一为Float.MAX_VALUE；有限乘法溢出饱和而不是转成零，普通NaN/Inf仍拒绝。新增真实猪处决/普通NaN对照验证，不能因为“处决不重构”就忽略实际经过新入口的旧调用。
