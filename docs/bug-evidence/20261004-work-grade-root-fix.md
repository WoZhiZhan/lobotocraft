## 根因与共同规则

原 `WorkManager.WorkSession` 和工作选择界面都通过员工总等级选择偏好矩阵Ⅰ—Ⅴ列。候选原作 `CreatureModel.GetWorkSuccessProb` 则按工作对应单项等级取列：

| 工作 | 对应单项 |
| --- | --- |
| 本能 | 勇气 |
| 洞察 | 谨慎 |
| 沟通 | 自律 |
| 压迫 | 正义 |

不是所有玩家的总等级被写死Ⅴ。错误出现在混合属性：例如总等级Ⅴ、自律Ⅰ的沟通曾读取Ⅴ列。一罪与百善在本mod现有矩阵和加成规则下，该场景真实提取前概率由错误95%修正为90%。

新增34行左右的不可变 `WorkAttributeLevels`，记录四项Ⅰ—Ⅴ级并提供 `levelFor/columnFor`。服务端会话、工作选择界面、原已按单项计算的工作经验都复用同一映射，不添加物种名单、不新建可配置概率引擎。

## 实际改动与边界

- `WorkManager`基础概率按实际解析后的工作类型取单项列，不按请求类型或总等级取列。
- 员工总等级仍用于准入 `getRequiredEmployeeLevel()`，未降低异想体工作门槛。
- 自律原始值额外加成、95%上限、观察/装备/核心加成、重复工作惩罚、既有异想体动态修正保留。
- 基础列与自律加成仍是会话开始快照，未额外改变工作中途改属性的行为；按次提取的异想体专属修正仍动态执行。
- `OpenWorkScreenPacket`改传四项等级，而非一个总等级；界面用同一映射显示该项基础偏好。它仍不是包含所有加成的最终提取概率，不将基础与最终显示混为同一数据。
- 网络协议39→40，客户端与服务端必须同版本更新，防止旧客户端按旧字段数量误解新包。未改存档属性格式。
- 缺能力上下文默认单项Ⅰ；EX参与概率仍按Ⅴ，与既有规则一致。
